# 秩序管理插件需求

管理员可以通过「警告@xxx」，「警告@yyy 7天」,「警告@yyy 15 天」的方式，指定警告某用户。警告后边一定只有天数，且格式一定是\d+\b+天，其他情况均视为无效内容，忽略即可
管理员可以通过「撤销@xxx」的方式，撤销对某用户的最后一条警告
管理员可以通过「以无暗者之名净化@xxx」的方式，移除30天内，对xxx用户的所有警告记录
任意成员可以通过发送「警告列表」，获得当前被警告的用户，以及警告过期时间
任意成员可以通过发送「信用分」「信用分列表」、「党人碑」，获得最近30天中，用户被警告次数排行榜前10名

允许指令两端、关键词与 @ 之间，以及提及结束后出现空白，但响应其他格式。关键词均要求整条消息匹配。手打 @、@所有人、真实 @ 多人、提及后包含其他非空白内容时，均忽略该消息。显示名可包含空格，目标身份按成员 ID 匹配。

# 整体说明说明

1.  在local-data下，群id, 例如54420135791@chatroom为文件夹名，记录和该群组相关的所有信息，作为群组数据库文件夹
2.  在群组数据库文件夹下，创建「秩序管理.json」、「秩序管理-history.json」文件，以json格式，记录违规内容
3.  每次读取/写入前，先读取整个json，将过期数据迁移至`秩序管理-history.json`，然后再读取内容，返回操作

# 功能说明

1. 管理员名单可以在插件中，按群组配置
2. 警告记录，要记录以下信息
   1. 被警告人(用户名、群昵称、id)
   2. 警告时间
   3. 警告预计过期时间(默认24小时)
   4. 警告发出人(用户名、群昵称、id)
   5. 警告是否生效中: true/false
   6. 警告失效时间
   7. 警告失效操作人: 具体用户/系统
   8. 警告失效原因: 未失效/超时过期/撤销/被无暗者净化
   9. 备注
3. 秩序管理.json 中只记录当前生效的警告
4. 警告失效(非生效中)后，移入秩序管理-history.json，分为2个key，一个是last30day，另一个是other，里面是警告列表。other中列表长度超出1000后，按日期顺序，移除距今最远的记录
5. 撤销/净化后，都要更新失效时间、失效操作人、失效原因
6. 警告过期后，自动更新，切换到失效状态
