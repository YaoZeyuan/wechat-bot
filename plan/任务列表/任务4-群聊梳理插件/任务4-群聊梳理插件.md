# 群聊梳理插件需求

在群内通过指令整理本地微信聊天记录。插件调用全局 AI 生成 Markdown 群聊纪事，在电脑上渲染为适合手机阅读的 PDF，再通过 Sender 发回触发指令的群。

## 启用与配置

- 插件默认关闭，在目标群的「群配置」中启用。
- 在「全局配置」设置默认 AI 的 API Base、API Key、模型及群聊纪事提示词。
- PDF 渲染依赖本机可执行的 Edge 或 Chromium 系浏览器。群内发送依赖 Sender 和已连接的手机。

## 指令

整条消息匹配，允许首尾空白以及关键词与参数之间的空白。

| 指令              | 行为                                                                              |
| ----------------- | --------------------------------------------------------------------------------- |
| 梳理              | 梳理指令发出时所属的北京时间当天。已有缓存时直接使用。                            |
| 梳理 20261115     | 梳理指定日期的全部记录，日期格式为 YYYYMMDD。                                     |
| 重新梳理          | 删除北京时间当天的缓存并重新生成。                                                |
| 重新梳理 20261115 | 删除指定日期的缓存并重新生成。                                                    |
| 梳理 50           | 梳理触发消息之前最近 50 条记录。支持 50 至 999 条，历史不足时使用实际找到的记录。 |

无法解析的日期返回日期格式提示。匹配到条数指令且小于 50 时，回复「最小梳理50条，请检查后重试」。其他格式不触发。

## 聊天记录与 PDF

- 以当前群本地数据库为数据源。按日期梳理时读取指定自然日的全部记录。按条数梳理时，以触发消息为边界，排除该消息，再按时间正序整理。
- 复用聊天记录导出的文本格式。发言者优先显示群昵称，其次显示微信昵称。链接以本地记录中的信息呈现。
- 使用全局群聊纪事提示词生成 Markdown，再渲染成网页并打印为 PDF。页面宽度为 393 CSS 像素。正文高度在渲染上限内时生成一张长页，超出时使用 393 × 852 CSS 像素分页。
- 日期报告命名为「群聊梳理-群原名-YYYYMMDD.pdf」。缺少群原名时使用群 ID。按条数生成的文件命名为「群聊梳理-最近N条.pdf」，N 为实际读取条数。

## 缓存与预览

- 日期 PDF 按微信账号、群 ID、日期缓存，保留 30 天，在生成或读取日期报告时清理过期缓存。重新梳理会先删除对应日期的缓存。
- 按条数生成的报告绑定当前任务，不复用日期缓存。
- 群配置中的「预览 PDF」支持选定日期并在电脑上打开。已有日期缓存时直接使用，预览只在本机显示。

## 日志与验收

- 群内任务在「Sender 日志」中记录触发消息、读取范围、模型调用、PDF 生成或缓存命中，以及手机发送结果。PDF 就绪后可在日志中打开查看。
- 首次梳理指定日期应生成 PDF。再次执行同一日期应命中缓存。「重新梳理」应重新调用模型生成。
- 「梳理 50」应读取触发消息之前的记录。记录不足时，文件名使用实际条数。「梳理 49」应给出最小条数提示。
- 本地预览应能打开 PDF。群内触发成功后，PDF 应送达原群。
