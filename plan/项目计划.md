## 首期范围（已确认）

项目纯自用、开源、非商业化。CipherTalk-Backup 先作为独立读取端使用。若后续需要复制或修改其源码，再核对对应模块的许可及开源分发要求。

首期完成 Windows 微信消息的只读接入、群白名单、关键字路由和待发送内容生成。待发送记录供手机端后续接入，首期验收到本地查看记录为止。实际发消息延后，届时可参考 FlowBot。

### 实施顺序

1. 构建并验证本机 CipherTalk-Backup 的独立 CLI。用 JSON 模式检查连接，列出会话并查询测试群。验证当前微信版本能读取新消息，以及数据能否提供稳定的群 ID、消息 ID、发送者、时间和正文。
2. 在 wechat-bot 定义读取适配器和统一消息格式。首版按群 ID 轮询白名单，持久化增量游标和去重键；首次启动从当前进度开始监听，历史查询单独用于统计。
3. 配置「群 ID → 关键字 → 处理函数」。先用本地注册表做一条示例指令，处理函数接收消息与只读查询能力，返回回复内容。
4. 将结果写入本地待发送记录，保存目标群 ID、显示名、触发消息 ID、正文和生成时间。验收时确认测试群的新指令只生成一条记录，重启后不会重复生成，其他群的相同指令不会触发。

### 首轮实测配置

- 读取端为已登录的 Windows 微信 4.2.0.13。测试群为「我们都是姚泽源」，接入时从 CLI 查询并核对实际群 ID。
- 首条指令为「测试」。整条文本匹配后生成固定文本「测试成功」，只写入本地待发送记录。
- 后续回复内容支持纯文本、图片、TXT 文件、PDF 文件和网页分享。文本回复可附带引用和群成员 @。首期只验收纯文本。

CLI 构建通过后，先验证当前微信版本能读取测试群，再请测试群发一条新的「测试」用于端到端验收。


### 后续回复类型与定位

- **文本、图片、TXT 和 PDF**。文本保存正文，图片和文件保存本地路径。
- **网页分享**。待发送记录保存 URL 和目标群。发送端先在微信内打开链接，再用页面的转发功能分享到目标群，验收以群内实际收到的分享内容为准。链接打不开或页面无法转发时，记录失败原因。
- **引用**。默认关闭。开启时必须指定一条目标群内的消息。引用触发消息时直接使用事件里的群 ID 和消息 ID；引用其他历史消息时，按群 ID 限定范围，再用发送者、时间段、关键词筛选候选。候选多条时由调用者选定，最终保存消息 ID，并保留发送者、时间和文本摘要供手机端定位。待发送记录支持引用信息，实际引用操作取决于手机端能否定位该原消息。
- **@ 群成员**。待发送记录可带一组目标群成员。优先保存可取得的稳定成员 ID，并保留群内显示名；同名时需要确认具体成员。发送端通过微信的群成员选择界面完成真正的 @。

后续实测需要分别确认网页能否从微信内转发、数据库中的原消息能否在手机界面唯一定位，以及群成员 ID 能否映射到微信的 @ 选择项。
